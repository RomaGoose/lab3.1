# ЛР1. Универсальное AVL-дерево

НИЯУ МИФИ. Вариант «Бинарное дерево поиска», модификация 1.1 «Балансировка».

Шаблонное AVL-дерево на C++20 с терминальным интерфейсом, тестами и замерами производительности.

## Устройство системы

| Сущность | Назначение и связи |
| --- | --- |
| `avl_tree<T, Compare>` | Владеет корнем, хранит размер и компаратор; выполняет операции над деревом. |
| `node` | Хранит значение, высоту и владеет двумя потомками через `std::unique_ptr`. Уничтожение корня освобождает всё дерево. |
| `Compare` | Задаёт порядок значений и определяет дубликаты. Дерево хранит собственный объект компаратора. |
| Терминальное приложение | Управляет независимыми деревьями чисел и записей `{id, name}`. Записи сравниваются по `id`. |

Бенчмарк использует контейнер и сохраняет замеры в CSV. Python-скрипт читает CSV и строит графики. 

## Функциональные требования

- Вставка, поиск и удаление уникальных значений с автоматической AVL-балансировкой.
- Размер, проверка пустоты, все шесть обходов и печать структуры дерева.
- Пользовательские типы и компараторы, копирование и перемещение дерева.
- Интерфейс для чисел и записей, обработка ошибочного ввода, генерация нового числового дерева по количеству, диапазону и seed.
- Модульные тесты основных алгоритмов и графики производительности.

## Нефункциональные требования

- Вставка, поиск и удаление — O(log N) при постоянной стоимости сравнения; память — O(N).
- Автоматическое управление памятью через RAII, доступ только для чтения через const-интерфейс.
- Ограничения типов проверяются концептами C++20; корректность — GoogleTest и сборкой с ASan/UBSan.

## Сборка и запуск

Нужны компилятор с C++20, CMake ≥ 3.20, Make, Git и установленный GoogleTest. FTXUI v7.0.3 загружается при первой сборке интерфейса. Для графиков нужны Python 3, `venv` и `pip`; зависимости устанавливаются автоматически в `build/`.

Команды выполняются из корня репозитория. Запуск и тестирование сначала собирают выбранный режим.

| Действие | Debug | Release | ASan/UBSan |
| --- | --- | --- | --- |
| Собрать | `make bd` | `make br` | `make bs` |
| Запустить интерфейс | `make rd` | `make rr` | `make rs` |
| Запустить тесты | `make td` | `make tr` | `make ts` |

`make bench` запускает замеры в Release, `make pl` строит графики из полученного CSV.

## Тесты и результаты

48 тестов проверяют основные операции, повороты, баланс, обходы, копирование, перемещение, пользовательские типы, исключения и генератор.

Замеры: от 10 000 до 1 000 000 элементов, возрастающий и случайный порядок, пять повторов, медиана времени N операций. Неуспешные запросы меньше минимального ключа. Пример на Intel Core i7-14650HX, GCC 16.2.1, Release:

| Миллион операций | Возрастающий порядок, мс | Случайный порядок, мс |
| --- | ---: | ---: |
| Вставка | 92,283 | 329,047 |
| Успешный поиск | 79,510 | 232,866 |
| Неуспешный поиск | 12,224 | 6,709 |
| Удаление | 65,059 | 333,388 |

CSV и графики PNG/SVG создаются локально в `benchmarks/results/` и исключены из Git.
